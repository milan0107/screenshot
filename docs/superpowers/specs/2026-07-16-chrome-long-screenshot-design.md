# Chrome 长截图扩展设计

## 1. 目标

构建一个基于 Chrome Manifest V3 的扩展。用户可在网页上按住鼠标拖出矩形选区；当指针接近滚动区域顶部或底部时，扩展自动纵向滚动，使选区能够跨越多个屏幕。确认后，扩展逐屏捕获、裁剪和拼接，最终直接下载一张 PNG。

第一版同时支持：

- 浏览器主页面纵向滚动；
- 单个页面内部纵向滚动容器；
- 高分屏与非 100% 页面缩放；
- 常见固定栏、吸顶元素和图片懒加载页面。

## 2. 非目标

第一版不支持：

- 横向自动滚动；
- 嵌套多层滚动容器的联合截图；
- 跨域 iframe 内部内容控制；
- 虚拟列表未挂载的历史内容；
- `chrome://`、Chrome Web Store 等禁止脚本注入的页面；
- 截图后的二次编辑或预览裁剪。

## 3. 技术路线

采用 `chrome.tabs.captureVisibleTab()` 捕获当前可见标签页，通过程序化滚动获取多个分段，再使用 Canvas 裁剪和拼接。

不采用以下替代路线：

- Chrome Debugger Protocol：需要敏感的 `debugger` 权限，且内部容器仍需滚动拼接；
- DOM 转 Canvas：跨域图片、字体、视频、Canvas、复杂 CSS 与 iframe 的还原可靠性不足。

## 4. 架构与组件

### 4.1 Service Worker

职责：

- 响应扩展图标点击；
- 协调 Content Script 与 Offscreen Document；
- 串行调用 `captureVisibleTab()`；
- 管理任务状态、超时和取消；
- 调用下载 API 保存 PNG。

Service Worker 不处理 DOM 或 Canvas 绘制。

### 4.2 Content Script

职责：

- 注入遮罩、选框和确认工具条；
- 识别主页面或最近的单个纵向滚动容器；
- 将指针坐标转换为滚动内容坐标；
- 在拖选阶段执行边缘自动滚动；
- 在捕获阶段设置目标滚动位置并返回实际位置；
- 报告视口、滚动区域、选区和布局状态；
- 临时隐藏需去重的固定/吸顶元素；
- 最终恢复页面状态。

### 4.3 Offscreen Document

职责：

- 解码各段截图；
- 按实际截图缩放比裁剪；
- 按内容坐标拼接并消除重叠；
- 检查画布尺寸和预计内存；
- 编码最终 PNG Blob。

### 4.4 统一滚动表面接口

主页面和内部容器实现同一逻辑接口：

- 获取边界、滚动位置、视口高度和内容高度；
- 设置纵向滚动位置；
- 将视口坐标转换为内容坐标；
- 锁定与恢复交互状态。

这样可复用选区、分段和拼接算法，并把两类滚动对象的 DOM 差异隔离在适配层内。

## 5. 滚动对象识别

鼠标按下时，从命中元素向祖先遍历，寻找最近且同时满足以下条件的元素：

- 计算样式 `overflow-y` 为 `auto`、`scroll` 或 `overlay`；
- `scrollHeight > clientHeight`；
- 可见尺寸足以形成有效选区。

找到后锁定该内部容器；否则使用页面根滚动元素。一次任务只允许一个滚动表面，拖动过程中不切换。

内部容器的横向选区被限制在容器可见边界内。第一版不自动横向滚动。

## 6. 用户交互

1. 用户点击扩展图标，页面进入选区模式并显示半透明遮罩。
2. 鼠标按下时记录起点和滚动表面。
3. 按住鼠标拖动形成矩形。指针接近滚动表面顶部或底部时自动滚动；速度随指针接近边缘而增加。
4. 选区以滚动内容 CSS 像素记录，滚动后仍可连续扩展。
5. 鼠标松开后显示 `确认截图`、`重新选择`、`取消`。
6. 用户确认后锁定交互并隐藏扩展 UI，开始捕获。
7. 成功后直接下载 PNG；失败时显示简短错误提示。
8. 成功、失败或取消后均恢复页面原状态。

按 `Esc` 可取消当前选择或截图任务。捕获已经开始时，取消在当前一次捕获结束后生效。

## 7. 捕获与拼接数据流

1. 保存原始滚动位置、内联样式和待处理固定元素状态。
2. 根据选区、滚动表面可见高度和实际可滚范围生成目标分段。
3. 将滚动表面移动到每段目标位置。
4. 等待至少两次 `requestAnimationFrame`，并等待布局进入稳定状态；图片最多额外等待约 1 秒。
5. Content Script 返回实际 `scrollTop`、滚动区域视口矩形和当前布局指标。
6. Service Worker 调用 `captureVisibleTab()` 获取当前标签页 PNG。
7. Offscreen Document 根据实际截图宽度与 `window.innerWidth` 的比值计算像素缩放，不单独依赖 `devicePixelRatio`。
8. 每段按滚动区域视口矩形和选区交集裁剪；拼接位置由实际滚动内容坐标决定。
9. 对相邻分段的重叠区域只保留一次；末段仅保留选区剩余高度。
10. 所有分段完成后编码单张 PNG，交由后台下载。
11. 在 `finally` 语义下恢复页面状态。

截图任务严格串行，避免滚动状态与捕获结果错配。

## 8. 固定与吸顶元素

捕获开始前，Content Script 记录与选区相交的 `position: fixed` 和已处于吸顶状态的 `position: sticky` 元素。

- 首段正常保留这些元素；
- 后续分段临时设置为不可见，避免在长图中重复出现；
- 每段捕获后保持任务所需状态，任务结束时统一恢复原样。

第一版不尝试重新排版被固定元素覆盖的首段内容；结果以用户在首段视口看到的内容为准。

## 9. 坐标与稳定性

所有业务坐标使用 CSS 像素。截图裁剪坐标使用运行时测得的横纵缩放比转换为位图像素，并在边界处使用一致的取整策略。

不假设设置的滚动位置等于实际位置。每次滚动后必须读取实际 `scrollTop`，用它计算裁剪和拼接偏移，从而处理：

- 浏览器像素取整；
- 平滑滚动样式；
- 到达滚动末端；
- 动态内容引起的轻微高度变化。

捕获期间临时禁用 `scroll-behavior: smooth`，并阻止鼠标、滚轮和键盘改变滚动状态。如果滚动区域边界、选区有效范围或内容高度发生无法补偿的明显变化，任务中止并提示重新截取。

## 10. 尺寸与资源限制

创建最终 Canvas 前检查浏览器实际可用尺寸，同时应用以下第一版安全上限：

- 任一位图边长不超过约 30,000 像素；
- 总像素数不超过约 200 MP；
- 预计内存超过安全阈值时不开始拼接。

超过限制时明确提示用户缩小选区，不生成截断或损坏的文件。具体阈值集中配置，方便根据兼容性测试调整。

## 11. 错误处理与恢复

任务使用唯一 ID，所有跨组件消息都携带任务 ID，过期消息直接丢弃。

以下情况会中止并显示可理解的错误：

- 当前页面禁止脚本注入或截图；
- 活动标签页在任务中途改变；
- 滚动容器被删除或尺寸显著改变；
- 捕获或图片解码失败；
- 输出超过尺寸或内存限制；
- 用户取消或任务超时。

恢复逻辑必须覆盖成功、失败、超时和取消路径，恢复：

- 原始滚动位置；
- `scroll-behavior` 与临时内联样式；
- 固定/吸顶元素可见性；
- 页面交互和扩展遮罩。

## 12. 权限

第一版使用最小化权限集合：

- `activeTab`：用户主动点击扩展后访问当前页面并捕获；
- `scripting`：按需注入 Content Script；
- `offscreen`：创建离屏拼接环境；
- `downloads`：直接保存 PNG。

不申请 `debugger`、`<all_urls>` 或持久站点访问权限。若 Chrome 对当前捕获流程要求额外权限，以实际最小可运行权限为准并在实现阶段验证。

## 13. 测试策略

### 13.1 单元测试

- CSS 坐标到位图坐标转换；
- 主页面与容器内容坐标转换；
- 分段目标生成；
- 实际滚动位置偏差补偿；
- 相邻段重叠裁剪；
- 末段高度；
- Canvas 尺寸与内存限制。

### 13.2 浏览器集成测试

- 普通长页面；
- 单个内部纵向滚动容器；
- 从页面或容器中部开始选取；
- 高分屏和不同页面缩放比例；
- 固定导航栏与吸顶表头；
- 懒加载图片和动态高度内容；
- 到达滚动底部时不足一整屏；
- 截图中途取消和人为触发错误。

### 13.3 人工验收

- 扩展图标可进入选区模式；
- 边缘自动滚动速度自然且可控；
- `确认截图`、`重新选择`、`取消` 与 `Esc` 行为正确；
- PNG 尺寸与选择范围一致；
- 长图无明显重复、断层或错位；
- 任务结束后页面滚动位置、样式和交互恢复。

## 14. 验收标准

在 Chrome 当前稳定版的普通网页中，用户能够对主页面或单个内部纵向滚动容器完成跨屏矩形框选，并直接下载一张 PNG。常规静态页面的输出不得出现肉眼可见的分段重复、空隙或坐标错位。失败和取消不能遗留遮罩、锁定状态或被隐藏的页面元素。
