# 高清模式重新框选 Design

> 已作废：交互改为「松手自动截图，完成后只弹一个菜单（格式/保存/复制/关闭）」，画质/高清入口已移除。见 `2026-07-19-post-capture-menu-design.md`。

## Goal

修复高清模式在确认截图后才改变标签页缩放、导致响应式网页布局变化并使旧框选坐标错位的问题。

## User Flow

1. 用户完成首次框选后，点击“高清”。
2. 扩展保存当前标签页缩放并将该标签页临时设为 150%。
3. 扩展立即清除旧选区，保留“高清”已开启状态；用户在新的实际布局中重新框选。
4. 用户确认后按重新框选得到的坐标截图；成功、失败、取消、超时或重新进入选择模式都会恢复原缩放。

## Architecture

- 内容脚本把“开启高清”和“退出高清”作为独立消息发送给 Service Worker；不再等到 `CAPTURE_REQUEST` 后才改变缩放。
- Service Worker 开启时读取原缩放并在响应中返回；内容脚本保存该数值，并在取消或截图请求中回传，避免 MV3 Service Worker 休眠后丢失状态。每个标签页的缩放读写在单个 Worker 生命周期内串行执行。
- 选择控制器将“重置选区”与“关闭高清”拆分：重新框选保留高清和已放大的布局，取消/退出选择才请求恢复原缩放。
- 截图控制器不再在捕获开始时设置 150% 缩放，因此不会在旧选区坐标已生成后改变页面布局。

## Error Handling

- 开启缩放失败时保留原选区、高清按钮维持关闭，并显示现有的中文截图错误提示。
- 关闭缩放失败时仍释放本地选择 UI；下一次高清操作会重新读取当前浏览器缩放。
- 已开启高清但未确认截图时，按 Escape、点击取消、重新点击扩展图标或重新进入选择模式都会恢复缩放。
- 截图过程沿用现有 `finally` 的恢复顺序：先恢复页面状态，再恢复原缩放；原始截图错误优先于恢复错误。

## Testing

- 选择控制器测试：点击高清先发送开启消息，成功后清除旧框选；后续确认的 payload 仍包含 `highQuality: true`。
- 选择控制器测试：取消一个尚未确认的高清选区会发送关闭消息。
- Service Worker 测试：开启高清按 `getZoom -> setZoom(1.5)` 执行并返回原缩放；即使模拟 Worker 重启，取消仍可用回传的原缩放恢复。
- 截图控制器测试：已在选择阶段应用高清时不再次设置 150%，并在成功和失败时恢复选择阶段保存的原缩放。

## Constraints

- 普通截图流程不改变。
- 高清模式仍使用 PNG，不进行插值放大。
- 不合并或依赖未合并的提速分支。
- 不尝试换算响应式网页缩放前后的旧选区坐标。
